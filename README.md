# 인공인의 밤 — 인지용카의 초대장 v6

12월 17일 행사 QR 퀴즈와 개인 초대장 웹사이트입니다. Python 3.10 이상에서 실행합니다.
v5의 참가·발급·관리 기능과 팀 이미지 파일을 이어서 사용합니다. 첫 화면은 발신인을 숨기고, 마지막 초대장에서 인지용카를 공개합니다.

## Vercel 배포

Vercel은 `vercel_app.py`를 통해 기존 앱을 실행하며, Neon Postgres에 참가 기록을 저장합니다.
Vercel 환경 변수에 `DATABASE_URL`, `ADMIN_PASSWORD`, `DB_SCHEMA=inguin_event`, `PUBLIC_HTTPS=1`을 설정합니다.
비밀번호와 DB 접속 문자열은 GitHub에 올리지 않습니다. Preview와 Production은 서로 다른 DB 브랜치를 사용합니다.
배포 후 `/api/health`에서 DB 연결 상태를 확인하고, 관리자는 `/admin`으로 접속합니다.
로컬 실행은 기존 SQLite DB를 계속 지원합니다. 클라우드는 Python 3.12를 사용합니다.

## Windows 실행

1. ZIP을 **새 폴더에** 압축 해제합니다. v4 실행 폴더에 덮어쓰지 마세요.
2. `setup_windows.bat`을 실행합니다. 관리자 비밀번호와 DB를 만듭니다. QR 생성 패키지도 ZIP에 포함되어 있습니다.
3. `start_windows.bat`을 실행합니다. 이 창을 열어 두세요.
4. 참가자: `http://localhost:8000` / 관리자: `http://localhost:8000/admin`

Python이 없다면 python.org의 Python을 설치하고 설치 시 PATH 옵션을 선택하세요.
글꼴·이미지는 ZIP에 포함되어 있으며 실행 중 외부 글꼴 서비스에 연결하지 않습니다.
관리자 비밀번호는 첫 설정 시 출력되고 프로젝트의 `.env`에 저장됩니다.
이 배포 ZIP에는 운영 비밀번호나 참가 기록이 포함되지 않습니다.

## v5에서 v6으로 바꾸기

1. 기존 서버를 종료하고 v5 폴더 전체를 백업합니다.
2. v6 ZIP을 **새 폴더에** 압축 해제합니다.
3. v5의 `.env`와 `data` 폴더를 v6 폴더에 복사합니다. 두 곳에서 같은 DB로 동시에 실행하지 마세요.
4. v6의 setup → start를 실행합니다. 기존 비밀번호·발급 번호·현장 확인 기록을 유지합니다.

호환성을 위해 DB 파일명은 `data/event_v5.db`를 그대로 사용합니다.
기본 v5 문제 은행이면 v6 이야기형 문제로 자동 전환하며, 기존 완료 기록은 유지합니다.
진행 중인 참가자는 재시작 후 새 문제를 받습니다. 관리자가 직접 수정했던 문제 은행은 자동으로 덮어쓰지 않습니다.
파일 교체 후 화면이 이전처럼 보이면 브라우저를 새로고침하세요.

## v4 참가 기록을 이어 쓰기

v4 서버를 종료하고 DB 파일을 별도로 백업하세요. **v6 setup 실행 전에** 아래 명령으로 복사합니다.

```text
python migrate_v4.py "C:\기존폴더\data\event_v4.db"
```

그다음 setup과 start를 실행합니다. 기존 초대장 번호·발급 일시·현장 확인 기록을 유지하며,
미완료 참가자는 재접속할 때 v6 문제로 다시 시작합니다. 원본 DB는 수정하지 않습니다.
이미 v6 DB가 있으면 이 도구는 덮어쓰기를 거절합니다. 관리자 세션은 새 로그인으로 시작합니다.

## 행사 QR 접속

관리자 페이지의 QR 주소에 참가자 휴대폰에서 접근 가능한 서버 주소를 입력하고 QR을 생성합니다.
같은 Wi-Fi에서는 서버 PC의 IPv4 주소를 사용합니다. 예: `http://192.168.0.20:8000`.
`.env`의 `HOST=0.0.0.0`으로 LAN 접속을 허용한 뒤 서버를 다시 실행하세요.
`localhost`와 `127.0.0.1`은 참가자용 QR 주소가 아닙니다.
학교 Wi-Fi의 단말 간 통신 차단, Windows 방화벽, PC 절전 상태는 현장에서 별도 확인해야 합니다.
외부 인터넷에서 접속하려면 공개 서버와 HTTPS 구성이 필요합니다. 이 ZIP은 자동으로 배포하지 않습니다.
HTTPS 뒤에서 운영할 때 `.env`의 `PUBLIC_HTTPS=1`로 바꾸세요.

## 참여와 운영

- 이름 + 학번 끝 두 자리로 참가합니다. 같은 조합은 같은 참가자로 취급합니다.
- 그림 속담 1문제, 서재의 추리 1문제, 봉인된 초대 1문제를 무작위로 받습니다. 문제 은행은 총 9문제입니다.
- 서술형은 서버에서 유니코드 정규화와 공백 제거 후 인정 정답과 비교합니다. 임의의 동의어나 오탈자를 자동 인정하지는 않습니다.
- 답과 인정 정답은 참가자 API에 포함되지 않습니다. 서버가 세 답을 모두 확인한 뒤 초대장을 발급합니다.
- 발급 수량 제한은 없습니다. 실제 처리량은 서버와 저장 공간에 따라 달라집니다.
- 발급된 초대장에는 중복 방지용 고유 번호가 있고, 현장 확인은 1회만 가능합니다.
- 관리자는 참여·발급·현장 확인 통계, 참가 검색, CSV 내보내기, 문제 수정, 접속 QR 생성을 이용할 수 있습니다.
- 관리자 검색은 이름 일부·이름과 끝 두 자리(붙여 쓰기 허용)·초대장 전체 번호를 지원합니다. 동명이인은 목록으로 표시하며, 50건을 넘으면 검색어를 좁히도록 안내합니다.
- 화면의 발급 목록은 최근 300건입니다. 전체 기록은 CSV로 받습니다.
- 문제 수정 시 기존 발급 초대장은 유지하고, 미완료 참가자는 재시작해야 합니다.
- 이름과 끝 두 자리가 모두 같은 동명이인은 구분할 수 없습니다. 본인 인증 서비스는 아닙니다.

## 디자인과 접근성

Noto Serif KR, Noto Sans KR, Cormorant Garamond를 로컬 파일로 제공합니다. OFL 라이선스는 `static/fonts`에 있습니다.
버건디 배경·평면 금박 티켓·실제 텍스트 조판으로 구성했습니다. 팀의 세 움파룸파 이미지와 웡카 복장 인지용은 원본 그대로입니다.
봉투 대신 포장 띠가 벗겨지는 짧은 연출 후 티켓이 나타납니다.
티켓과 별도 버튼으로 CSS 3D 앞뒷면 뒤집기가 가능하고 Enter/Space도 지원합니다.
움직임 줄이기 설정에서는 전환을 생략합니다. 인쇄/PDF는 앞뒤 두 면을 출력하도록 구성했습니다.

## 수수께끼 방향

세 상자의 진실과 거짓, 서재의 책 순서, 열쇠와 문, 편지의 첫 글자, 사탕의 규칙, 두 문지기의 대답을 이용합니다.
단순 암산 문제와 영화 줄거리 지식 문제는 기본 은행에 없습니다. 팀 이미지 속담 세 장은 그대로 유지합니다.
고전 논리 수수께끼 형식과 [EDC 논리 퍼즐](https://elementarymath.edc.org/resources/logic-puzzles/),
[Lewis Carroll의 이야기형 퍼즐](https://www.gutenberg.org/ebooks/29042)을 참고해 행사에 맞는 새 문구로 구성했습니다.
모든 분기 추리 문제는 가능한 경우를 열거해 정답이 하나인지 검사했습니다.

기존 .env와 data 폴더는 그대로 보관합니다. DB 파일을 배포 ZIP으로 덮어쓰지 마세요.
인터넷 배포 시에는 지속되는 DB 저장소와 운영 비밀번호를 구성하고 참가자용 주소로 QR을 생성하세요.
